# Interaction Notes

報告 UI・手動確認・質問形式に関する project-local メモ。

## 手動確認の出し方
- 手動確認項目は本文で提示する。
- AskUserQuestion では `OK / NG番号` だけを聞く。
- 手動確認依頼と次アクション選択を同じ質問に混ぜない。
- 小変更ごとに確認せず、方向比較または実装後の acceptance bundle に集約する。
- 高主観な変更では、完成品を先に作り込まず、現状・異質な 2-4 方向・最小の比較材料・選択後に固定する評価軸を先に示す。

## 禁止パターン
- AskUserQuestion の `question` に Markdown テーブルを入れる
- 選択肢を commit / しない の yes/no で埋める
- 既知文脈を「詳細を教えてください」で再質問する
- `続行してよいですか`、routine test の実行許可、直接関係する修正の個別許可を求める
- 実装、テスト、status 更新、commit、push を別々の Prompt または承認段階に分ける
- 既存正本を調べず、restart / runtime / roadmap / decision / report 用の新規文書を増やす

## ユーザーが嫌う形式
- 安全側の一般論だけで可逆な開発まで停止する
- 同じ軸の言い換えにすぎない選択肢や、進路を狭める二択
- Prompt が細切れで、成果が見える前に何度も往復を要求する進め方
- 大きな UI・コンテンツ成果を初見で提示し、その後に微修正だけを反復する進め方
- ファイル名やテスト名だけを列挙し、workflow や意思決定への効果が分からない報告
- 読みにくい崩れた表

## 報告メモ
- 現在地、今回何が動くようになったか、意図して決めなかったこと、検証鮮度、次に異なる bottleneck を解く 2-4 入口を自然文でつなぐ。
- 選択肢は `Advance / Audit / Excise / Explore / Verify / Publish` 等の異なるレーンから必要なものだけを選び、完了すると何が可能になるかを示す。
- status は `HANDOVER.md` に一度だけ書き、古い時系列節を追加し続けない。履歴は Git に任せる。
- repo をローカルで開かない人には GitHub 上の `HANDOVER.md` を現在地入口として案内する。別の外部 status 面を採用する場合は自動投影し、手動の第二正本にしない。
